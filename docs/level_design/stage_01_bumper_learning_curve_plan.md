# Stage 01 범퍼 단계 학습 레벨 디자인 계획

작성: 2026-08-09 · 브랜치 `Level_Design/Wave_01` · 근거: [범퍼 컨셉 기획서](https://iambiguity.atlassian.net/wiki/spaces/~712020ee2aad7553a24fbdbcd73713654d1e91/pages/18087939) (2026-08-05)

## 0. 문제 진단 — 왜 지금은 단계 학습이 안 되는가

**4개 웨이브(1·2·3·보스)가 전부 동일한 범퍼 6개를 그대로 노출한다.**
모든 범퍼는 `Resources/Prefabs/wave/base/wave.tscn`의 `Bumpers` 노드에 있고,
각 웨이브 씬은 이를 상속만 할 뿐 추가·제외·이동을 전혀 하지 않는다.

| 자리 | 노드 | 현재(전 웨이브 공통) | 위치 |
|---|---|---|---|
| 상단 중앙 | BumperCenter | 단추 | (0, −288) |
| 좌상 날개 | BumperUpperLeft | 솜 | (−432, −144) |
| 우상 날개 | BumperUpperRight | 단추 | (432, −144) |
| 좌하 날개 | BumperLowerLeft | 용수철 인형 | (−432, 144) |
| 우하 날개 | BumperLowerRight | 장난감 북 | (432, 144) |
| 하단 중앙(발사 경로) | BumperCannon | 태엽 대포 | (0, 144) |

즉 플레이어는 **웨이브 1 첫 발사에서 Normal·Bounce·Shot 세 타입을 동시에** 만난다.
기획서의 학습 순서(Normal → Bounce → Shot)와 정면으로 어긋난다.

## 1. 설계 원칙 — "자리는 고정, 주인공만 교체"

베이스의 6자리 다이아몬드 배치를 **무대**로 유지하고, 웨이브마다 **한 타입씩만 새로 등장**시킨다.

- 새 타입은 항상 **이전 웨이브에서 단추가 있던 익숙한 자리**에 나타난다.
  → 학습 부담이 "새 위치+새 규칙"이 아니라 "아는 위치의 새 규칙" 하나로 줄어든다.
- 좌우 대칭 자리에 **다른 재질을 마주 세워 A/B 비교**를 만든다
  (웨이브 1: 좌상 솜 vs 우상 단추 — 같은 각도로 쳐 보면 감속/가속 차이가 즉시 체감된다).
- 발사 첫 충돌 지점 (0, 144)는 학습 앵커다: 웨이브 1·2에선 "신뢰의 단추",
  웨이브 3부턴 같은 자리에 대포가 서서 첫 공이 자연스럽게 Shot 튜토리얼로 이어진다.

## 3. 구현 방식 (씬 상속 안전)

기존 씬·베이스는 건드리지 않고, 각 웨이브 씬에서 에디터 도구(`WaveAuthoringTools`)와 동일한 직렬화만 쓴다:

- 상속 범퍼 제외: 루트 `disabled_bumper_paths` (Bumpers 기준 상대 경로) — 원본 무손상, 복원 가능
- 신규 범퍼: 웨이브 씬 로컬 노드로 `Resources/Prefabs/bumpers/presented/*_vfx.tscn` 인스턴스 추가
- 로스터 계약: `expected_bumper_kind_ids`를 실제 로스터로 갱신
- 웨이브 1·2는 도구 규약대로 `enforce_stage_bumper_limits = false`
  (`Stage01BumperLayout.tres`의 wave_01 항목이 기획서와 달라 범위 검사가 불가 — §4-C 참고)
- 보스는 `authored_bumper_wave_index = 3` + 범위 검사 유지 (보스 로드아웃과 정합)

## 4. 검토 항목과 형락님 결정 (2026-08-09 확정)

**A. 삼각형 보드 → 폐기 확정.** 스테이지 01은 8각 보드로 간다.
레거시 프로토타입 `scenes/dev/legacy/waves/wave01_triangle.tscn`도 전면 삭제 (참조 0건 확인 후 제거).

**B. 대포 사양 → 현행 픽스.** 발사 방향 7개 · 선택 시간 2.0초 · A/D 순환 선택이 확정 사양이다.
기획서(2~3방향·0.8초·WASD 직접 선택)와 다르지만 **의도된 튜닝**이므로 기획서 쪽으로 "고치지" 말 것.
(발사 앵커는 종류 공유 리소스라 보스/웨이브별 사격선 분리는 애초에 불가 — 분리가 필요해지면 전용 .tres 변형 필요.)

**C. `Stage01BumperLayout.tres` wave_01 로드아웃 → 현행 픽스.**
.tres(Normal 2~3 + Bounce 4~4)를 기획서 값으로 정렬하지 않는다.
웨이브 1 씬은 `enforce_stage_bumper_limits = false` + `expected_bumper_kind_ids` 계약으로 검증하므로 충돌 없음.

**D. 보스 씬 잔재** — 목표 점수가 베이스의 `cursed_toy_demo` 자리표시자(25만~100만)를 상속
(보스는 HP 기반 승리라 실해는 없음, 표기용 정리 대상). 좌·우상 범퍼(±432,−144)는 보스 팔 스윕
반경(~440px) 안 — 보스전 압박 요소로 수용 가능하나 인지 필요.

**E. 속도 상한 이원화** — 기획서의 "보드 일반 최대 1,540px/s"는 범퍼·발사기·플리퍼에 각각 걸려 있고
공 자체 상한은 2,000~5,000. 범퍼 외 가속원이 생기면 1,540을 넘을 수 있음 (시스템 설계 참고 사항).

**F. 목표 점수 재검토 여지** — 웨이브 1이 전부 100점 Normal이 되면서 종전보다 목표 1,000 도달이
약간 느려짐. 플레이테스트에서 길게 느껴지면 800으로 하향 검토.

**G. Track 타입** — 기획서대로 스테이지 01 제외 (코드도 데이터 전용 스텁, 전략 미구현 — 문제 없음).
