# 범퍼 아트 리소스 (2026-08-05 STEP1)

기획서: `범퍼 7종 비주얼·사운드 제작 가이드 v0.2` (강보현, 104쪽).
산출물: `docs/bumper_guides/` — 제작 가이드 · 형태 마스터 생성기 · Leonardo 프롬프트.

## ★ 다음 사람이 밟기 쉬운 지뢰 3개

### ① 기획서 7종과 코드 목록이 다르다

- **장난감 기차는 개발 취소됨.** 기획서 5-5절에 명시돼 있는데 그 아래로 형태·색상·연출·SFX
  규격이 그대로 남아 있어 안 읽으면 그대로 만들게 된다. **만들지 않는다.**
- **구슬 미끄럼틀은 코드에 슬롯이 아예 없다.** `VisualStyle` 열거값·`.tres`·씬 셋 다 없다.
  `BumperType.TRACK` 은 있지만 TRACK 을 쓰는 범퍼 정의가 하나도 없다.
  STEP1 마스터는 만들어 뒀지만 **연결은 개발 선행 작업**이다.
- 반대로 코드에만 있는 4종(`STARLIGHT_BROOCH` `GOLDEN_GEARS` `CRESCENT_NEEDLE`
  `FORGOTTEN_STAR_BELL`)은 기획서에 아트 방향이 없다. 수리 부품 시스템에서 왔고
  전부 `CONCEPT_ONLY` → [[repair-parts-system]]. 아트 범위에서 제외했다.

### ② 범퍼에는 텍스처를 넣을 슬롯이 없다

`bumper_visual.gd` 의 `_draw()` 가 `visual_style` 열거값으로 도형을 직접 그린다.
**PNG 를 만들어도 그대로는 안 붙는다.** `BumperPresentationSettings` 에 `texture` 추가 +
`_draw()` 분기가 선행돼야 한다. 제안 코드는 제작 가이드 5절에 적어 뒀고 **반영하지 않았다**
(`dev/bumper_reapair` 에서 수리 부품 작업 중이라 충돌 위험 + 승인 필요).

같이 옮겨야 하는 것: 비활성 `alpha 0.28`, 복구 예고 점멸, **`_draw_durability()` 실밥 스티치**.
내구도 표시는 텍스처와 별개라 텍스처 경로에서도 계속 그려야 한다.

### ③ 알파 bbox 를 또 밟지 말 것

공에서 두 번 밟았다 → [[ball-texture-fixed]]. 표시 크기 계산이 **텍스처 긴 변**으로 나눈다.
`bumper_master.py` 의 `finalize()` 가 크롭 → 정사각 패딩 → 리사이즈로 강제하고
생성 시 채움률을 찍는다. **솜만 세로 91.6%** 인데 구름형이라 bbox 가 정사각이 아니어서 그렇다.
가로가 100%이므로 표시 지름은 가로 기준으로 맞는다.

## 확정 규격 (코드 실측)

| 범퍼 | kind_id | 타입 | 충돌 | 표시 |
|---|---|---|---:|---:|
| 단추 | `stage01_button` | NORMAL | 88 * | 92 * |
| 솜 | `stage01_cotton` | NORMAL | 96 | 104 |
| 용수철 인형 | `stage01_spring_doll` | BOUNCE | 104 | 112 |
| 장난감 북 | `stage01_toy_drum` | BOUNCE | 120 | 128 |
| 태엽 장난감 대포 | `stage01_clockwork_cannon` | SHOT | 112 | 128 |

\* `.tres` 에 값이 없어 `bumper_settings.gd` 기본값.

마스터 1024×1024 RGBA. 표시 지름과 충돌 지름의 4~8px 차이는 **외곽 잉크선 두께로 소비**한다.

## 팔레트에서 바뀐 것

기획서 v0.2 의 핵심 개정: **아이보리/청록은 범퍼의 필수 주색이 아니다.**
범퍼마다 재질·역할에 따라 버건디·황토·금색·목재갈색·회보라를 주색으로 쓴다.
청록/아이보리는 세계관 연결색으로 일부만. 전체 HEX 표는 제작 가이드 2절.

빨강은 기능색 "빨강 = 피해·위험" 을 보호해야 하므로 대면적 금지. 버건디는 채도를 낮춰 쓴다.

## STEP1 에서 형태로 확정한 것

프로젝트 규칙대로 **실루엣은 AI 에 안 맡긴다** → [[staged-art-pipeline]].
`bumper_master.py` 가 좌표로 그린다. 손그림 흔들림은 저주파 노이즈(`wobble_circle`/`wobble_path`).

- **용수철 인형만 프레임 2장** — 기본(얼굴이 충돌면) / 타격(얼굴 눌림 + 용수철 노출).
  기획서가 "두 상태의 형태 차이로 Bounce 를 전달"하라고 명시한다. 재생 구조는 미설계.
- **대포는 +X(오른쪽) 기준**으로 그렸다. `_draw_cannon()` 이 이미
  `get_selected_launch_direction()` 을 읽으므로 각도 보정이 필요 없다.
  포구까지 받침대 원 **안에서** 끝나게 해 충돌 실루엣과 어긋나지 않게 했다.

### 제작 중 걸린 것

- 굵은 스트로크에 흔들림 진폭을 크게 주면 **경로가 자기 자신과 교차해 삐죽삐죽해진다.**
  미끄럼틀 통로에서 밟았다. 진폭을 낮추고 보간 밀도를 줄여야 한다.
- 솜 외곽선을 모폴로지 침식으로 뽑으려다 4096px 에서 사실상 멈췄다.
  **덩어리를 선 굵기만큼 키운 합집합 → 원래 크기 합집합** 순서로 그리면 연산 없이 같은 결과가 나온다.
- 흔들 목마 받침을 발굽에서 떼어 놓으면 **웃는 입으로 읽힌다.** 발굽 바로 아래에 붙여야 한다.
