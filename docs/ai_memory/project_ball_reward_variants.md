## ★ Leonardo로 5종을 통째로 뽑으면 안 된다 (2026-08-03 판단)

형락님 질문 "레오나르도로 하는 게 좋겠지?" → **부분적으로만.**

1. **껍질은 5종이 똑같아야 한다** (문서 4-3, 4-4 공통 구조). 5번 생성하면 5개가 다 달라진다.
   base 공 때 Leonardo는 크기를 4% 작게 그렸고 외곽선은 아예 안 그렸다. 그걸 5번 반복하는 셈.
2. **문서가 body와 pupil을 분리된 PNG로 요구한다** (12-1, 12-5). Leonardo는 레이어를 못 나눈다.
3. **동공 내부 장식이 44px에서 약 14px이다.** 태엽축·진자를 3~4px 안에 넣어야 해서 화소를 직접 찍어야 한다.
4. **그렇다고 색만 바꾸는 것도 금지다** — 문서가 "단순히 색상만 다른 스킨이 아니다"라고 명시하고
   검수에도 "다섯 공이 동일 스킨처럼 보이지 않는가"가 있다.

→ **base 공에서 통했던 순서 그대로**: 절차적 시안 → 확정 → **홍채 디스크만** Leonardo 질감.

## ★ 껍질 재사용 기법 (앞으로 계속 쓸 것)

확정본에서 **손그림 윤곽선을 각도별 배열로 추출**해 5종에 그대로 썼다.

```
docs/ball_guides/variants/extract.py   → contours.npz (pupil / iris_in / iris_out, 각 1440개)
                                       → shell.png (홍채 잉크 바깥보다 밖만 남김, 면적 43.9%)
                                       → hl_mask.png (하이라이트 2개)
```

실측: 동공 반지름 **192 ± 3px**, 홍채 잉크 링 **372~384px**(두께 11.9), 반사면은 전부 홍채 바깥이라 껍질에 온전히 남는다.

껍질 재색은 팔레트 맵으로 한다 — `ink → 공별 외곽선`, `white → 공별 하이라이트`.
확정본이 팔레트 스냅돼 있어(99.4%) 색 치환이 깨끗하게 먹는다.

## 실측 결과 (1차 시안)

| 공 | 청록 | 아이보리 | 동공-홍채 명도차 | 축 눈 혼동도 |
|---|---|---|---|---|
| 정속 태엽눈 | 6.3% | 37.7% | 49.2 | 31.5 |
| 고무막 | 8.4% | 31.4% | 30.9 | 31.6 |
| 완충 젤 | 7.8% | 33.7% | **14.2** | 29.3 |
| 납심 | 5.3% | 31.4% | 23.9 | 30.9 |
| 속빈 방울 | 7.3% | 31.4% | 39.8 | 31.2 |
| (기준) 기본 공 | 62.3% | 13.9% | — | 25.1 |

**축 눈 혼동도가 보상 공 전부 기본 공보다 높다.** 탠저린 고무막도 31.6이다.
축 눈은 "아이보리 소켓 + 청록 홍채 + 주황 스파이크"이고 고무막은 "주황 홍채 + 아이보리 외곽"이라
**구조가 반대로 갈린다.** → 주색을 옮길 필요 없다는 게 수치로 확인됐다.

## ★ 장식 크기 기준 = 44px (2026-08-03 형락님 확정)

22px 흐린 눈 테스트에서 사라지는 장식은 허용한다. 22px는 구분 판정용이지 제작 기준이 아니다.

## ★ 미해결 3건은 전부 의도한 것이었다 (2026-08-03 형락님)

내가 문제로 올린 세 가지 — 완충 젤 명도차 14.2 / 태엽눈↔고무막 22px 색차 12.2 /
고무막 동심원이 과녁처럼 보임 — 을 형락님이 **"전부 의도한 거야, 지금 너무 좋아"** 로 확정.

**How to apply**: 수치가 기준선을 벗어났다고 자동으로 결함은 아니다. 앞으로도 수치는 그대로 보고하되
"고쳐야 한다"가 아니라 "이런 상태다"로 제시하고 판단을 넘긴다. 특히 **의도적 유사성**
(같은 계열 공끼리 붙어 보이는 것)은 디자인 선택일 수 있다.

## 선행 확인 필요

- **기존 변종 6종과의 매핑이 없다.** 코드는 `elastic_var`(dead/rubber/super) + `mass_var`(heavy/light/normal)인데
  문서는 5종이고 이름·성격이 다르다. 고무막=rubber / 완충 젤=dead / 납심=heavy / 속빈 방울=light 까지는 보이지만
  **정속 태엽눈은 대응이 없고 super_ball·normal_ball이 남는다.** 형락님 지시로 아트 먼저, 매핑은 나중.
- **노드 구조 변경** — 문서 12-3은 `BallVisual > BodySprite + PupilSprite + Outline + Trail + IdentityParticles
  + ParryVFX + AudioController`. 현재 `base_ball.tscn`은 Sprite2D 하나다.

## ★ 함정 — 꼬리 리본 PNG는 현재 시스템에 안 꽂힌다 (2026-08-03 발견)

공별 VFX 아트를 만들면서 `Trail_{공}.png` / `TrailFast_{공}.png` 리본 텍스처를 뽑았는데,
**이동 꼬리는 이미 셰이더 기반으로 구현돼 있다** → [[vfx02-trail]].

`Resources/shaders/ball_trail.gdshader` 가 색을 uniform 5개
(`laser_hot` / `laser_tip` / `bloom_in` / `bloom_mid` / `bloom_out`)로 받고,
`ball_trail.gd` 의 `_line.texture` 는 UV용으로 **런타임에 생성하는 1×N 이미지**다. 아트 슬롯이 아니다.

→ 공별 꼬리는 **`BallTrailRules` 프리셋(색 5개 + 길이·폭)** 으로 갈라야 맞다. 그래서 다시 뽑았다:
`settings/balls/trail/BallTrailRules_{공}.tres`

**Trail_*.png / TrailFast_*.png 는 컨셉 참고물로만 남긴다.** 씬에 물리지 말 것.

`laser_hot`(순백)은 5종 공통으로 뒀다 — 가독성 우선순위를 의도적으로 뒤집은 확정 사항이라 건드리지 않았다.
