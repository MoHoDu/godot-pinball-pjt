# 아트 리소스 생성 파이프라인

## 툴 체인 (본인이 2026-07-31 정리)
- **신규 이미지 생성 = Leonardo.Ai** (Pro 계정, $30 결제 완료)
- **세부 디테일 편집 = GPT** (또는 nanobanana pro2, Canva)
- VFX도 생성 예정

## 개발 프로세스 원칙 (2026-07-30 회의에서 전환)
카테고리(개발/아트/VFX)를 따로 굴리지 않는다. **오브젝트 하나를 정하고 그것의 개발·아트·VFX를 함께 만들어 조립**한다. 레고 조립 방식.
문서도 대기업식 세분화를 버리고 가독성·즉시 검색 위주로 재편.

Why: 소규모 팀이라 빠른 소통과 빠른 개발이 우선.
How to apply: 아트 요청을 받으면 해당 오브젝트의 기획/개발 페이지를 함께 보고, 개발 진척에 맞춰 필요한 에셋만 뽑는다.

## 리소스 통과 기준 (강보현 체크리스트 요약)
검수의 핵심은 "예쁜가"가 아니라 **게임에서 역할과 상태가 즉시 읽히는가**.

즉시 FAIL:
- 역할·상태를 바로 알아볼 수 없다
- 실제 게임 크기에서 형태가 뭉개진다
- 배경 장식이 공·플리퍼보다 눈에 띈다
- 장식과 실제 충돌 범위가 크게 다르다
- 일반 작동과 패링 성공을 구분할 수 없다
- 기능색이 규칙과 반대로 쓰였다
- VFX·사운드가 공의 흐름 판단을 방해한다
- 특정 게임 디자인을 그대로 모방했다

판정: PASS / 조건부 PASS / FAIL. 양식 = 리소스명·담당자·판정·필수 수정사항·재검수 여부.

## 플리퍼 제작 원칙
**마스터 플리퍼 1개를 복제·회전해서 쓰는 모듈 방식.** 충돌 크기와 기본 실루엣은 고정.
보드별 차이는 색상 오버레이 / 회전축 장식 / 표정·눈동자 / 작은 데칼 / 작동 VFX·사운드로만 만든다.
