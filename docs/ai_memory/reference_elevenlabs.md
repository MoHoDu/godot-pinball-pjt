# ElevenLabs 효과음 — 조사 정리

2026-08-07 공식 문서 기준. 웹 UI 와 API 를 둘 다 쓴다.

## 1. 파라미터

| 항목 | 값 | 우리가 쓰는 값 | 왜 |
| --- | --- | --- | --- |
| Duration | 0.1~30초, 또는 auto | **0.5초** | 앞 30~250ms 만 쓴다. 길면 크레딧만 나간다 |
| Prompt Influence | 0~100%, **기본 30%** | **90~100%** | 30% 면 모델이 프롬프트를 흘려듣는다 |
| Looping | on/off | **off** | 원샷이다. 그리고 **켜면 WAV 를 못 받는다** |

★ **Prompt Influence 기본값이 30% 다.** 이걸 안 올리면 아무리 정확한 프롬프트를
써도 모델이 자기 마음대로 간다. 우리가 겪은 저수율의 상당 부분이 여기였을 수 있다.

★ 높이면 **결과의 다양성이 줄어든다.** 그래서 4개가 다 비슷하게 나온다.
같은 프롬프트를 다시 돌려도 비슷하다면 그건 운이 아니라 **프롬프트 문제**다.
프롬프트를 고쳐야지 재시도해봐야 소용없다.

## 2. 웹 UI vs API

| | 웹 | API |
| --- | --- | --- |
| 한 번에 나오는 개수 | **4개** | 1개 |
| 받는 형식 | MP3 44.1kHz / **WAV 48kHz** | 지정한 포맷 |
| 크레딧 | 화면에 표시됨 (0.5초 = 2크레딧) | 호출당 과금 |

★ **WAV 48kHz 로 받는다.** 우리 파이프라인이 48kHz 라 리샘플이 없다.
MP3 는 손실 압축이라 어택 트랜지언트가 흔들린다.

★ **WAV 는 Looping 이 꺼져 있을 때만 받을 수 있다.**

★ 웹이 한 번에 4개를 준다. 같은 크레딧으로 API 보다 4배 효율이다.
**소재 탐색은 웹, 확정된 프롬프트의 대량 생성은 API** 가 맞다.

## 3. ★ 생성물이 공개될 수 있다

웹 UI 하단에 이런 문구가 있다.

> 생성된 내용은 다른 사용자가 다운로드할 수 있도록 탐색 페이지에 공유될 수 있습니다. **비활성화**

탐색(Explore) 탭에 커뮤니티 생성물이 뜨는 구조다. **대회 제출물이라면 반드시
'비활성화' 를 눌러야 한다.** 우리 프롬프트와 결과물이 그대로 공개될 수 있다.

## 4. 모델이 알아듣는 오디오 용어

문서가 명시한 것들이다. 자연어보다 이쪽이 정확하다.

| 용어 | 뜻 |
| --- | --- |
| **one-shot** | 반복 없는 단발 — 우리가 매번 쓰는 것 |
| **impact** | 충돌·접촉음 |
| **whoosh** | 공기를 가르는 이동음 |
| **ambience** | 배경 환경음 |
| **loop** | 반복 구간 |
| **stem** | 분리된 한 레이어 |
| **braam** | 크고 금관적인 극적 히트 |
| **glitch** | 오작동·불규칙 |
| **drone** | 지속되는 질감 |

## 5. 프롬프트 규칙 — 문서 + 우리 실패에서 얻은 것

문서가 말하는 것:
- 짧고 분명하게. "Glass shattering on concrete"
- 여러 소리가 섞인 장면은 **따로 뽑아서 합친다.** 한 프롬프트에 몰지 않는다
- 오디오 용어를 알아듣는다

우리가 실패로 배운 것 ([[reference_sound_spec]] §9 과 같은 내용):
- **소리 명사가 결과를 지배한다.** "knock" 을 쓰면 유리를 요구해도 나무가 온다.
  같은 배치에서 "crack" 은 5/6 성공, "knock" 은 0/6 이었다
- **물체는 하나만.** "A struck by B" 를 쓰면 모델이 충돌 장면을 만든다
- **작은 소리를 달라고 하지 않는다.** 음량은 런타임이 건다.
  작게 달라고 하면 노이즈 플로어를 받는다
- **부정문보다 긍정문.** "no repetition" 보다 "then silence" 가 낫다
- "creak"·"groan" 은 모델에게 **높은 마찰음**이다. 처지는 소리를 원하면
  "thunk"·"hum" 처럼 낮은 몸통을 가진 명사를 쓴다

## 6. API 키 한도

계정 잔액과 **키별 한도는 별개다.** 2026-08-06 에 키 한도 2000 크레딧이
소진돼 생성이 막혔는데 계정에는 37,624 크레딧이 남아 있었다.
API 로 대량 생성이 필요하면 대시보드에서 **키 한도를 먼저 올려야 한다.**
