# 보드 아트 파이프라인 (2026-08-02 형락님 확정)

## 확정된 3단계

1. 보드의 원형이 되는 **마스크/레퍼런스 이미지를 하나 만든다**
2. 그 이미지를 레퍼런스로 써서 **보드에 텍스처를 채운다**
3. **외곽 삼각형 4개는 전부 마스크로 오려낸다**

Why: 한 프롬프트에 형태·재질·장식을 다 넣으면 Leonardo가 실루엣을 먼저 무너뜨린다.
보드 아트는 v1~v5까지 리테이크한 이력이 있어 단계를 쪼개 검수 지점을 만든다.

## ★ 원칙 1 — 실루엣은 AI에게 맡기지 않는다 (2026-08-02 실측 확정)

**생성물에서는 색과 표면만 가져오고, 형태는 도면 좌표로 우리가 확정한다.**

Why: Nano Banana 2 결과를 서브픽셀 측정하니 대각 각도는 19.89°(스펙 19.98)로 거의 완벽했지만
변 길이 배분이 어긋났다 — 평평한 변 700→758, 대각 819→790, 충돌 경계와 최대 약 10px 차이.
**4장 전부 같은 방향 같은 크기의 오차**(정점 X = 740.5/742.3/742.7)라 재생성·시드 변경으로 안 고쳐지는 체계적 편향이다.

How to apply:
- 실루엣 오차를 프롬프트로 고치려고 재생성하지 않는다. 생성 횟수 낭비다.
- **검수 기준은 "실루엣이 정확한가"가 아니라 "표면이 깨끗한가"** 다.
- 마스킹 절차: ① 생성물 정점을 서브픽셀 직선 적합으로 측정 → ② 도면 폴리곤에 맞추는 변환 적용
  → ③ 안쪽으로 수 px 파고들어 오려냄(rim 잔재 제거) → ④ 알파 마스크 씌워 2240×1260 출력

**단, 대상이 원 하나면 얘기가 다르다.** 2026-08-03 공 생성에서는 같은 편향이 안 나타났다
(중심 오차 0.35px, 반지름 오차 1.2px, 잔차 평균 0.29px). 형태가 단순하고 여백판이 크기를 못 박아준 덕 → [[ball-glass-eye]]

## ★ 원칙 2 — 텍스처 생성 레퍼런스는 여백판으로 (2026-08-02)

**보드가 프레임에 닿는 레퍼런스를 쓰면 마스킹만으로 rim을 못 없앤다.**

Why: 생성물이 도면보다 약 10px 바깥에 그려지므로 도면 폴리곤으로 오려내면
**대각 4변의 rim은 잘려나가지만 평평한 4변의 rim은 남는다**(보드 변이 화면 끝에 붙어 마스크 경계와 겹치기 때문).
결과는 대각엔 테두리 없고 상하좌우엔 있는 비대칭 보드.

How to apply: 텍스처 단계 레퍼런스는 도면을 92%로 축소해 여백을 준 판을 쓴다.
모델이 뭘 붙이든 여백 안에서 끝나고 8변이 똑같이 잘린다. 해상도 손실은 없다.

## 측정은 반드시 원본으로 (자책 기록)

썸네일 스크린샷으로 rim 폭을 20~30px으로 추정했는데 원본 2752×1536으로 재측정하니 **4~8px**이었다.
다운샘플 블러가 얇은 선을 부풀린다.

**2026-08-03 같은 실수를 반복했다.** Leonardo 그리드 썸네일만 보고 "공 동공이 대칭이라 방향성이 사라졌다"고
오판했는데, 상세 뷰로 열어보니 제대로 밀려 있었다. **검수는 반드시 원본 해상도 또는 상세 뷰로.**

## Nano Banana 2 실측 특성

- 기울기(각도)는 잘 보고 **정점 위치는 대충 본다**
- 표면 균일도는 기대 이상 (밝기 편차 0.5 이하의 완전한 단색)
- Style preset `Game Concept` 은 오브젝트 둘레에 밝은 rim을 붙인다 → **`None`** 을 쓸 것
- Leonardo의 "16:9" 2752×1536은 실제로 1.7917 (정확히 16:9는 1.7778). 2240×1260으로 갈 때 0.78% 가로 압축 필요
- **다운로드는 PNG가 아니라 JPG로 나온다.** 4배 다운샘플이 있으면 아티팩트는 지워진다
- 다운로드 파일은 형락님 다운로드 폴더로 가므로 프로젝트 폴더로 옮겨달라고 부탁해야 스테이징된다
