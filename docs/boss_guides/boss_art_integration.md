# 보스 아트 → 보스 시스템 연결 인계

> 2026-08-07 · 짝 문서: `boss_production_sheet.md` · 분리 도구: `boss_layer_split.py`
> **보스 런타임을 만드는 분에게.** 아트 쪽에서 준비한 것과 붙일 때 필요한 수치다.

---

## 0. 왜 직접 안 붙였나

작업 당시 보스 시스템은 `origin/feature/boss_*` 브랜치 19개에만 있었고,
**2026-08-08 현재는 main 에 머지돼 있다** (`stage1_teddy_boss_runtime.tscn` 등).
`resource/art` 쪽 파일(`anim/`·`vfx/`·`boss_art_test.tscn`)과 이름이 겹치는 것은
없어서 머지는 안전하다.

`resource/art` 에서는 **아트 리소스 + 독립 리그 + VFX + 검수 씬**까지만 만들고,
런타임과의 실제 결합(시그널 → `play_*`/`spawn_*` 호출)은 이 문서의 수치로 넘긴다.

## 3. ★ 현재 배치와 어긋나는 곳

`teddy_arm_sweep_attack.tscn` 의 플레이스홀더 폴리곤 기준이다.

| 항목 | 현재 씬 | 아트 | 차이 |
|---|---|---|---|
| 왼팔 어깨 | (-125, -72) | (-109.2, -116.3) | **+16, -44** |
| 오른팔 어깨 | (+125, -72) | (+110.0, -122.1) | **-15, -50** |
| 팔 길이 | 382 | 435 | +53 |
| 팔 폭 | 84 | 63 | -21 |
| 몸통 폭 | 300 | 254 | -46 |

어깨가 **44~50px 위로** 올라가야 한다. 아트의 어깨가 더 높다.

### 충돌체 권장값

기획서 8-2·4-1 수치를 아트에 맞춰 조정한 값이다.

| 부위 | 기획서 | 권장 | 사유 |
|---|---|---|---|
| 머리 | 330×190 | **그대로** | 아트가 379×239 라 안에 들어간다 |
| 몸통 | 300×300 | **250×250** | 아트가 254×262 라 300 은 삐져나온다 |
| 팔 폭 | 80~90 | **60** | 아트가 63 |
| 팔 길이 | 280~310 | **295 유지** | 아트 435 중 어깨에서 295 만. 나머지는 장식 |

마지막 항목은 기획서 4-1 의 "비주얼 크기보다 충돌체를 작게 사용해, 공이 곰의 귀나
풀린 실 장식에 억울하게 충돌하지 않도록 한다" 와 같은 방향이다.

### 확인이 필요한 수치 하나

어깨 간격이 **219** 라, 팔 충돌체를 295 로 잡으면 총 도달 범위가 **809** 가 된다.
기획서 8-2 는 "총 중앙 공격 범위 약 **580**" 이다.

세 갈래인데 어느 쪽인지 기획 확인이 필요하다.

- 팔 충돌체를 **180** 까지 줄이면 580 에 맞는다 (팔 절반 이상이 장식이 된다)
- 809 를 받아들이고 "보드 좌우 외곽 18% 는 팔 공격이 덮지 않는다" 를 실제 보드 폭으로 재검산한다
- 580 이 도달 거리가 아니라 **중앙에서 쓸리는 폭**을 뜻한다면 애초에 어긋난 게 아니다

세 번째일 가능성이 있어 문구가 애매하다.

## 4. 아트 리그

`scripts/boss_system/anim/boss_art_rig.gd` (`BossArtRig`)

**전투 로직이 없다.** 상태 전이·피해·스케줄링은 전부 런타임 몫이고, 이 노드는
시각 표현만 한다. 그래서 진행 중인 보스 런타임과 겹치지 않는다.

```gdscript
rig.play_idle()            # 상태 2 기본 대기
rig.play_telegraph()       # 상태 3 예고 — 몸이 아래로 압축
rig.play_attack()          # 상태 4 공격 — 위로 뻗으며 실루엣 전환
rig.play_recovery()        # 상태 5 경직 — 축 처진 채 천천히 복귀
rig.play_roar()            # 상태 7 포효 — 몸을 세우고 입이 찢어짐
rig.play_hit(dir)          # 상태 6 일반 피격 — 감쇠 진동 반동
rig.play_hit_strong(dir)   # 상태 9 강한 피격 — 크게 비틀림
rig.set_attack_progress(t) # 0~1. arm_active_sec 0.22 초에 맞춰 밀면 된다
rig.set_expression(&"...") # 표정만 따로 갈 수도 있다
```

`play_*` 는 전부 **보간으로 전환**된다. 즉시 그 자세가 필요하면 `play_*(true)`.
상태마다 자세(팔·눌림·기울기·오프셋)와 전환 속도가 `POSES` 에 정의돼 있다.
처음 구현은 상태가 즉시 스냅됐는데 "기본 대기 빼고 전부 어색" 하다는 지적을
받았다 (2026-08-07). 스냅과 몸 정지가 원인이었다.

피격은 상태가 아니라 **반동**이다. 현재 자세 위에 감쇠 진동(찌그러짐+기울기)이
얹혔다 잦아든다. `dir` 은 공이 온 쪽(-1 왼쪽, +1 오른쪽)이다.

하트핵은 `_process` 에서 알아서 박동한다. 진폭은 3.5% 로 묶어 뒀다.
**크게 하면 약점 아이콘처럼 보여 즉시 반려 사유**가 된다 (기획서 1-2: 핵은 약점이 아니다).

### 기본 대기 흔들림

기획서 상태 2 의 "몸이 좌우로 **불안정하게** 흔들림" 이다. 세 겹으로 쌓는다.

1. 몸이 **바닥을 축으로** 좌우로 기운다 (1.6°) — 중심에서 돌리면 배지처럼 빙글 돈다
2. 좌우로 조금 미끄러진다 (3.5px) — 회전만 쓰면 태엽 장난감처럼 규칙적이다
3. **팔이 몸을 늦게 따라온다** — 천 주머니가 매달린 느낌을 만드는 핵심이다

주기가 안 맞는 사인 둘을 겹쳐 "불안정하게" 를 만든다. 하나만 쓰면 규칙적으로 보인다.

인스펙터에서 `sway_degrees` / `sway_hz` / `sway_slide` / `breathe_amount` /
`arm_lag_gain` / `arm_lag_follow` 로 조절한다.

**폭을 키울 때 주의.** 가이드 20절이 "과한 흔들림으로 공 경로가 가려짐" 을 즉시
반려로 둔다. 보스가 화면 중앙의 큰 물체라 몇 px 만 움직여도 충분히 읽힌다.
테스트가 총 진폭 8° 를 상한으로 잡고 있다.

팔을 크게 들면 흔들림이 25% 로 죽는다. 공격 자세가 흔들리면 예고가 흐려진다.

### 상태별 표정

```gdscript
rig.set_expression(&"idle")        # 상태 2 기본 대기
rig.set_expression(&"telegraph")   # 상태 3 팔 공격 예고
rig.set_expression(&"attack")      # 상태 4 팔 공격
rig.set_expression(&"recovery")    # 상태 5 공격 후 경직
rig.set_expression(&"hit")         # 상태 6 일반 피격
rig.set_expression(&"hit_strong")  # 상태 9 강한 피격(정확한 반격)
rig.set_expression(&"roar")        # 상태 7 페이즈 전환 포효
```

팔 자세와 **독립**이다. 피격·포효는 표정만 바꾸면 된다.

**표정으로 바꿀 수 있는 것이 좁다.** 가이드 4-2 가 눈에 대해 흰자·동공·단추눈·발광을
전부 금지하고 **완전히 비어 있는 검은 구멍**만 허용한다. 그래서 눈은 구멍의
**모양과 기울기**만 바꾼다. 눈알을 그려 넣으면 즉시 반려다.

입도 4-3 이 "괴물의 이빨 입 → X, 찢어진 봉제인형의 틈 → O" 이고 **포효할 때만**
늘어난다고 못박았다. 그래서 **다물린 입은 아예 그리지 않는다** — 아트에 이미
그려져 있어서 덧그리면 입이 두 개가 된다. 벌어질 때만 원래 입을 삼키는 틈을 얹는다.

두 눈은 **서로 반대로** 기운다. 같은 방향으로 기울이면 얼굴이 통째로 돌아간 것처럼
보이고 표정이 안 읽힌다.

### 마스킹이 겪은 함정 (재분리할 때 필독)

`boss_layer_split.py` 가 전부 처리하지만, 왜 그 코드가 있는지 모르면 지우게 된다.

- **어깨 단면** — 잉크선을 따라 자르면 팔 끝이 폭 5px 쐐기가 된다. 대기에서는
  몸에 가려 안 보이지만 팔을 드는 순간 찢긴 단면이 드러난다. 둥근 캡으로 마감
- **캡 테두리** — 원을 통째로 두르면 리벳처럼 튄다. 새 실루엣 가장자리만 잉크
- **몸통 구멍** — 몸통에서 캡 영역을 빼면 가슴에 원형 구멍이 뚫려 뒤의 캡이
  비친다. 몸통은 그대로 두고 겹치게 둔다
- **잉크 기어오름** — 팔 마스크가 머리-어깨 홈의 외곽선을 타고 올라가 갈고리가
  매달린다. 피벗 위 6px 에서 자르고, 자른 잉크는 몸통에 돌려준다
- **팔 위의 천 패치** — 팔 가장자리에 걸친 패치가 "큰 성분" 장벽이 되거나
  부스러기로 삭제돼 팔에 물린 자국이 남는다. 접촉면 기준으로 팔에 귀속시킨다.
  단 크기 상한(2만px) 없이는 몸통 절반까지 팔로 넘어간다 — 몸통-팔 경계가
  몸통-머리 경계보다 길기 때문이다
- **접촉량은 소속을 말해 주지 않는다** — 아랫배 패치를 접촉량으로 팔에 보냈더니
  몸통이 패치 모양대로 파여, 팔을 들면 물린 자국이 남았다 (격자 실측으로 확인).
  **몸통 닫힌 실루엣 안에 있는 성분은 무조건 몸통**이다
- **경계 픽셀 분배는 성장이 아니라 최근접** — 성장 휴리스틱은 잉크를 한쪽으로
  길게 끌고 가 갈고리를 만든다. 다중 시작점 BFS 로 가장 가까운 코어에 주면
  경계 잉크가 중간에서 갈라진다
- **원본에서 팔이 몸통을 덮던 자리** — 가려진 몸통은 그려진 적이 없어 팔을
  들면 빈다. 복원면(`boss_body_under`)을 만들어 팔보다 뒤에 깐다

검증 기준은 **대기 합성 == 원본**이다. 여섯 장을 겹치면 원본과 픽셀 단위로
같아야 하고, 회전시켰을 때 단면·구멍·유령이 없어야 한다.

### 밟기 쉬운 것

- **z 를 음수로 두지 말 것.** 배경 노드보다 뒤로 가라앉아 팔이 통째로 사라진다.
  리그는 팔 뒤 0 / 몸 1 / 팔 앞 2 / 하트 3 을 쓴다
- **들어 올린 팔은 몸 앞으로 옮겨야 한다.** 뒤에 두면 머리에 가려 실루엣이 사라지고,
  실루엣 변화가 이 보스전의 전부다

### VFX (`scripts/boss_system/vfx/`)

`BossVfxLayer` — 리그의 **형제**로 두고 `rig_path` 를 꽂는다. 리그 자식으로
넣으면 대기 흔들림에 위험선까지 흔들린다. 예고는 읽기 정보라 흔들리면 안 된다.

**앞뒤 두 겹이다** (2026-08-08 재설계).
- 분위기 연출(잔상·연기·위험선)은 **보스 뒤**(z 0) — 실루엣을 안 가린다.
  씬에서 이 노드를 리그보다 **먼저** 둬야 같은 z 에서 뒤로 간다
- 타격 피드백(스파이크·솜·링)은 자식 `Front`(z 5) — 기획서 13-2 의 정보라
  가려지면 안 된다. 대신 수명이 짧아 공을 안 가린다

뒤 레이어에 그리는 것은 **실루엣 밖으로 나와야** 보인다. 위험선은 팔 반지름
1.06 배 바깥, 연기는 머리 위·옆 가장자리에서 시작하는 이유다.

| 연출 | 트리거 | 비고 |
|---|---|---|
| 예고 위험선 | **자동** (리그 상태 폴링) | 붓획 3개/팔, 맥동. 런타임 신호 불필요 |
| 팔 스윙 잔상 | **자동** (각도 **이력 리본**) | 올라갈 때도 내려갈 때도 궤적을 그대로 탄다 |
| 공 충돌 충격선 | `spawn_ball_impact(pos, dir)` | dir = 공이 튕겨 나간 방향. 그쪽으로 퍼진다 |
| 피격 푹+팡 | `spawn_hit(pos, dir, false)` | 타격선 + 검은 솜 파편 |
| 고콤보 피격 | `spawn_hit(pos, dir, true)` | 충격링 + 솜 두 배 |
| 포효 연기 | `spawn_roar()` | 봉제선에서 검은 연기 + 솜 떠오름 |

수치는 `settings/bosses/vfx/TeddyBossVfx.tres`.

**여기 없는 것** — 만들면 이중이 된다.
- 정확한 반격 VFX: 가이드 10절 메모 "패링 vfx 와 똑같은 거 쓰자!" → 기존 패링 재사용
- 히트스톱·화면 흔들림: 팔-공 충돌 히트스톱은 기획서가 금지. 시간 연출은 런타임 몫
- 암전 화면 프리셋: 화면 전체 연출이라 레벨/카메라 쪽이다

잔상은 스폰이 아니라 **추적**이다. 처음 판은 프레임마다 정지 부채를 스폰해서
팔이 내려갈 때 궤적을 안 따라왔다 (2026-08-08 지적). 지금은 팔 각도 이력을
기록해 리본을 매 프레임 다시 그린다. 리본 창 0.13s, 방향이 반전되면 거기서
끊는다 — 안 끊으면 폴리곤이 자기교차해 삼각분할이 터진다.

스타일은 아트와 같은 잉크 문법이다: 맨 draw_line 금지, 전부 끝이 가늘어지는
폴리곤, 큰 도형에는 잉크 림, 어두운 바깥 → 본색 → 밝은 코어 세 겹.
