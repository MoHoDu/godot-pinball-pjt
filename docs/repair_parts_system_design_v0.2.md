## 0. 재기획 결론

인형사의 수리 부품은 보드 밖에서 숫자만 올려 주는 유물이 아니다. 플레이어가 웨이브 사이에 보드의 수리 소켓에 직접 장착하고, 공이 실제로 접촉해 깨우는 공방 장치다.

이번 재기획의 핵심은 다음 한 문장으로 정리한다.

> 공으로 부품을 차례로 깨우고, 장난감 내부에 수선 경로를 만들어, 마지막에 하나의 수리를 완성한다.

각 부품은 PL 컨셉의 상징을 그대로 플레이 동사로 바꾼다.

| 부품 | PL 컨셉 | 플레이 동사 | 능력의 재미 |
|---|---|---|---|
| 별빛 브로치 | 완성, 마감, 축복 | 시작하고 완성한다 | 지정된 순서를 돌고 브로치로 귀환하는 샷 루트 |
| 황금 톱니바퀴 | 구동, 리듬, 생동 | 감고 터뜨린다 | 연속 접촉으로 회전 단계를 쌓고 과회전을 만든다 |
| 초승달 바늘 | 봉합, 연결, 복원 | 다음 부품과 잇는다 | 다른 부품을 제한 시간 안에 맞혀 추가 콤보를 만든다 |
| 잊혀진 별방울 | 울림, 반응, 여운 | 늦게 한 번 더 울린다 | 지연 타격으로 끊길 콤보를 살리고 리듬을 변주한다 |

기본 네 부품은 모두 공의 유효 접촉으로 작동한다. 단, 접촉을 계속 유지하는 동안 반복 발동하지 않고, 공이 분리된 뒤 다시 들어온 새로운 접촉만 인정한다.

## 1. 컨셉 해석 원칙

### 1-1. 반드시 유지할 요소

- 보상 명칭은 유물이 아니라 `인형사의 수리 부품`이다.
- 부품은 이름 없는 인형사가 장난감을 만들고 고치던 전문 도구다.
- 플레이어는 장난감을 공격하는 구슬이 아니라 저주를 해제하고 눈을 되돌려 주는 유리눈이다.
- 보상 선택은 전리품 획득이 아니라 자신의 수리함을 채우는 경험이어야 한다.
- 별, 톱니, 곡선 바늘, 방울의 실루엣과 상징을 능력의 행동에서도 읽을 수 있어야 한다.
- 황동, 금빛, 아이보리, 청록 유리, 실과 리본의 공방 재질 언어를 유지한다.

### 1-2. 시스템으로 새로 정의하는 요소

- 부품은 보드의 사전 제작된 수리 소켓에 장착한다.
- 장착된 부품은 보드 안에서 충돌 가능한 소형 장치로 존재한다.
- 접촉 위치와 부품 사이의 거리 때문에 같은 능력도 배치에 따라 가치가 달라진다.
- 모든 능력은 즉시 이해되는 기본 효과 하나와 숙련으로 얻는 추가 보상 하나를 가진다.
- 자동 발동이더라도 플레이어가 다음에 어느 부품을 노릴지 판단할 수 있어야 한다.

### 1-3. 지양할 설계

- `점수 +10%`처럼 보드 안에서 행동 변화가 없는 순수 패시브
- 공이 닿지 않아도 자동으로 계속 발동하는 효과
- 공의 위치를 순간이동하거나 기존 물리를 무시하는 효과
- 화면을 가리는 장시간 연출과 빈번한 전체 화면 효과
- 한 부품 안에 서로 무관한 효과를 세 개 이상 넣는 설계
- 다른 부품의 효과가 다시 자신을 호출하는 무한 연쇄

## 2. 핵심 플레이 경험

### 2-1. 한 공의 짧은 목표

플레이어는 공을 살리는 것 외에 다음의 작은 목표를 동시에 본다.

1. 지금 발동 가능한 부품을 확인한다.
2. 다음 플리퍼 타이밍으로 목표 부품 방향을 노린다.
3. 부품의 상태가 바뀌는 것을 보고 다음 목표를 고른다.
4. 두세 번의 성공적인 접촉으로 수선 연쇄를 완성한다.
5. 완성 보상으로 콤보 단계와 점수 흐름을 크게 끌어올린다.

부품은 플레이어에게 강제 미션을 주지 않는다. 안전하게 공을 살리는 판단이 항상 우선이며, 여유가 있을 때 부품 경로를 노리면 더 큰 보상을 얻는다.

### 2-2. 재미의 네 축

- 목표성: 무작위 반사가 아니라 다음에 맞힐 대상을 만든다.
- 리듬감: 즉시, 연속, 연결, 지연이라는 서로 다른 발동 박자를 제공한다.
- 배치 전략: 자주 맞는 안전 소켓과 어려운 고가치 소켓의 선택이 생긴다.
- 성장 체감: 동일 부품을 강화하면 숫자뿐 아니라 성공 가능성과 연쇄의 안정성이 증가한다.

## 3. 세션과 보상 루프

### 3-1. 전체 흐름

1. 세션 시작 전에 네 부품 중 시작 부품 하나를 선택한다.
2. 시작 부품을 여섯 개의 수리 소켓 중 하나에 장착한다.
3. 일반 웨이브를 진행한다.
4. 웨이브 종료 후 수리함에서 후보 세 개 중 하나를 선택한다.
5. 새 부품이면 수리함에 추가하고, 기존 부품이면 랭크가 상승한다.
6. 다음 웨이브 전에 부품을 장착하거나 위치를 교체한다.
7. 일반 웨이브 세 번을 거쳐 보스전에 진입한다.

시작 부품을 제공하는 이유는 일반 웨이브가 세 번뿐인 세션에서도 보스전 전에 네 부품을 모두 모으거나, 특정 부품을 집중 강화하는 선택이 가능하게 하기 위해서다.

### 3-2. 프로토타입 기본값

| 항목 | 기본값 | 의도 |
|---|---:|---|
| 시작 선택 | 네 종류 중 1개 | 첫 웨이브부터 시스템 경험 |
| 웨이브 보상 후보 | 3개 | 읽기 쉬운 선택 폭 |
| 무료 선택 | 1개 | 경제 시스템 없이 코어 재미 검증 |
| 재추첨 | 웨이브당 1회 | 빌드 실패 완화 |
| 부품 최대 랭크 | 3 | 짧은 세션에서 강화 체감 확보 |
| 수리 소켓 | 6개 | 위치 선택의 여지 제공 |
| 동시 장착 | 최대 4개 | 네 컨셉을 모두 보드에 표현 가능 |
| 전투 중 재배치 | 불가 | 물리 안정성과 판단 부담 관리 |

### 3-3. 후보 생성 규칙

- 첫 보상에는 현재 보유하지 않은 부품을 최소 하나 포함한다.
- 같은 후보 세 개가 모두 동일 계열이 되지 않게 한다.
- 최대 랭크 부품은 후보에서 제외한다.
- 새 부품과 기존 부품 강화가 함께 등장하도록 가중치를 보정한다.
- 보스 직전 보상은 현재 빌드에서 완성 가능한 선택을 최소 하나 보장한다.

## 4. 보드 소켓과 접촉 규칙

### 4-1. 소켓 배치

부품은 자유 좌표에 놓지 않는다. 기획자가 충돌 안전성을 검증한 `RepairSocket2D`에만 장착한다.

- 팔각형 메인 보드 기준 소켓 여섯 개를 사용한다.
- 중앙 보스 출현 영역, 플리퍼 회전 범위, 발사 직선, 드레인 입구에는 소켓을 두지 않는다.
- 쉬운 소켓 두 개, 중간 소켓 두 개, 위험하지만 반복 진입이 가능한 소켓 두 개로 난도를 구분한다.
- 소켓은 부품의 시각 중심, 충돌 반경, 발동 VFX 기준점을 함께 제공한다.
- 같은 부품도 어느 소켓에 놓는지에 따라 연속 접촉과 귀환 난도가 달라져야 한다.

### 4-2. 물리 형태

- 부품 루트는 `StaticBody2D` 또는 기존 범퍼 규칙을 따르는 별도 베이스 씬으로 만든다.
- 접촉 감지는 자식 `Area2D`가 담당하고, 실제 반사는 물리 충돌체가 담당한다.
- 프로토타입 권장 충돌 반경은 30~36 월드 유닛이다.
- 공 반지름 22 기준으로 좁은 틈에 끼이지 않도록 소켓 주변 최소 여유를 확보한다.
- 부품이 직접 공의 위치를 변경하지 않는다.

### 4-3. 유효 접촉

다음 조건을 모두 만족해야 한 번의 유효 접촉으로 인정한다.

1. 대상이 현재 활성 공이다.
2. 부품이 장착 및 활성 상태다.
3. 해당 공의 `instance_id`가 현재 접촉 집합에 없다.
4. 직전 발동 후 최소 0.12초가 지났다.
5. 효과 컨텍스트가 물리 접촉 `PRIMARY`다.

공이 접촉 영역을 벗어나면 접촉 ID를 해제한다. 이후 다시 들어오면 새 접촉으로 인정한다. 방울의 지연 타격이나 바늘의 봉합 타격처럼 코드로 생성된 `SECONDARY` 이벤트는 다른 부품을 발동하지 않는다.

## 5. 공통 발동 파이프라인

1. `RepairPartHitSource`가 공의 새로운 접촉을 검증한다.
2. 기존 `ComboHitSource.valid_hit_registered`를 통해 기본 콤보 타격을 적립한다.
3. `RepairEffectRouter`가 부품 정의와 현재 랭크를 읽는다.
4. 부품 고유 상태를 갱신하고 효과 명령을 만든다.
5. `RepairBallAdapter`, `RepairComboAdapter`가 기존 시스템의 공개 API를 호출한다.
6. `RepairPartFeedback`가 아이콘, 실, 회전, 방울 파동을 표시한다.
7. 로그에 실제 접촉과 2차 효과를 구분해 기록한다.

효과 처리 순서는 `접촉 중복 제거 → 기본 콤보 타격 → 부품 상태 갱신 → 2차 효과 → 피드백`으로 고정한다.

## 6. 부품 능력 상세

## 6-1. 별빛 브로치 - 마감의 별

### 컨셉 번역

별빛 브로치는 수리가 끝난 장난감에 마지막으로 다는 완성의 표식이다. 따라서 단순 점수 배율이 아니라, 한 번 시작한 수선 경로를 완성하고 브로치로 돌아왔을 때 큰 보상을 주는 피니셔가 된다.

### 플레이 규칙

1. 비활성 브로치에 닿으면 공에 `마감 표식`이 생긴다.
2. 제한 시간 안에 브로치가 아닌 서로 다른 부품 두 종류를 맞힌다.
3. 브로치의 별 팔 두 개가 차례로 켜진다.
4. 다시 브로치에 닿으면 `수리 완성`이 발동한다.
5. 완성 보너스 타격을 콤보에 추가하고 표식을 초기화한다.

같은 부품을 두 번 맞혀도 별 팔은 하나만 켜진다. 준비가 끝나기 전에 브로치를 다시 맞히면 제한 시간만 새로 시작하고 진행도는 초기화한다. 시간 초과, 공 낙하, 웨이브 종료 시 표식을 제거한다.

### 랭크 수치

| 랭크 | 제한 시간 | 필요한 다른 부품 | 완성 타격 가중치 |
|---:|---:|---:|---:|
| 1 | 6.0초 | 2종 | 3.0 |
| 2 | 7.0초 | 2종 | 4.0 |
| 3 | 8.0초 | 2종 | 5.0 |

완성 타격은 `ComboSystem.register_hit(finish_score_weight)` 한 번으로 처리한다. 콤보 횟수는 한 번만 증가하고, 큰 가중치는 콤보 정산 시 반영된다.

### 재미 포인트

- 브로치에서 출발해 다른 부품을 거쳐 다시 돌아오는 핀볼식 샷 루트를 만든다.
- 별 팔의 점등으로 현재 진행도가 즉시 보인다.
- 어려운 소켓에 브로치를 놓으면 완성 보상이 강하게 느껴진다.

### 안전 제한

- 한 공에 마감 표식은 하나만 존재한다.
- 방울의 지연 타격과 바늘의 추가 타격은 다른 부품 방문으로 계산하지 않는다.
- 완성 효과는 다시 브로치나 다른 부품 효과를 호출하지 않는다.

## 6-2. 황금 톱니바퀴 - 되감는 심장

### 컨셉 번역

황금 톱니바퀴는 멈춘 장난감에게 리듬과 생동을 돌려주는 심장이다. 공이 닿을 때마다 태엽이 감기고, 짧은 시간 안에 세 번 감으면 과회전이 터진다.

### 플레이 규칙

1. 톱니바퀴에 닿으면 현재 진행 방향을 유지한 채 안전한 속도 보정을 받는다.
2. 2.4초 안에 다시 톱니바퀴를 맞히면 회전 단계가 1씩 오른다.
3. 세 번째 유효 접촉에서 `과회전` 추가 가속이 발동하고 회전 단계가 0으로 돌아간다.
4. 제한 시간이 지나면 회전 단계가 0으로 초기화된다.

### 랭크 수치

| 랭크 | 접촉 가속 | 과회전 추가 가속 | 최대 단계 | 단계 유지 |
|---:|---:|---:|---:|---:|
| 1 | +90 px/s | +180 px/s | 3 | 2.4초 |
| 2 | +120 px/s | +240 px/s | 3 | 2.4초 |
| 3 | +150 px/s | +300 px/s | 3 | 2.4초 |

### 구현 공식

```text
current_speed = ball.linear_velocity.length()
requested_speed = current_speed + contact_boost
if wind_stack == 3:
    requested_speed += overdrive_boost
desired_velocity = ball.get_limited_velocity(direction * requested_speed)
impulse = (desired_velocity - ball.linear_velocity) * ball.mass
ball.apply_central_impulse(impulse)
```

공이 거의 정지한 경우 방향은 `톱니 중심 → 공 중심` 벡터를 사용한다. `Pinball.get_limited_velocity()`를 거치므로 공 종류별 최소·최대 속도 규칙을 침범하지 않는다.

### 재미 포인트

- 한 번의 접촉은 회복, 세 번의 접촉은 작은 잭팟처럼 느껴진다.
- 반복 진입이 가능한 소켓을 찾는 배치 전략이 생긴다.
- 기어 회전 속도와 톱니 점등으로 과회전까지 남은 횟수를 보여 줄 수 있다.

### 안전 제한

- 텔레포트와 위치 직접 변경을 금지한다.
- 공 고유 최대 속도를 초과하지 않는다.
- 과회전은 같은 물리 접촉 안에서 두 번 발생하지 않는다.

## 6-3. 초승달 바늘 - 달실 봉합

### 컨셉 번역

초승달 바늘은 찢어진 부분을 다음 조각과 이어 주는 도구다. 바늘 자체에서 점수를 끝내지 않고, 제한 시간 안에 다음 부품을 맞혀야 봉합이 완성된다.

### 플레이 규칙

1. 바늘에 닿으면 `달실`이 공에 연결되고 봉합 대기 상태가 된다.
2. 제한 시간 안에 바늘이 아닌 다른 부품에 닿으면 봉합이 성공한다.
3. 바늘 소켓과 대상 소켓 사이에 짧은 실 선이 그려진다.
4. `봉합 타격` 한 번을 콤보에 추가하고 대기 상태를 소모한다.
5. 시간 초과나 공 낙하 시 실이 끊어지고 효과가 사라진다.

바늘을 다시 맞히면 제한 시간만 처음부터 갱신한다. 방울의 지연 타격은 물리 접촉이 아니므로 봉합 대상으로 인정하지 않는다.

### 랭크 수치

| 랭크 | 봉합 제한 시간 | 봉합 타격 가중치 | 추가 콤보 |
|---:|---:|---:|---:|
| 1 | 3.0초 | 0.00 | +1 |
| 2 | 4.0초 | 0.25 | +1 |
| 3 | 5.0초 | 0.50 | +1 |

봉합 성공 시 `ComboSystem.register_hit(stitch_score_weight)`를 호출한다. 랭크 1도 점수 가중치는 없지만 콤보 횟수와 유지 시간을 한 번 더 확보한다.

### 재미 포인트

- 다음 부품을 맞혀야 한다는 짧고 명확한 목표가 생긴다.
- 콤보가 끊기기 직전에 봉합이 성공하면 실제로 흐름을 꿰맨 느낌이 난다.
- 바늘과 자주 맞는 부품을 멀리 배치할수록 조준 난도와 성취감이 커진다.

### 안전 제한

- 한 공에 봉합 대기는 하나만 유지한다.
- 봉합 타격은 다른 부품, 브로치 진행도, 새 봉합을 발동하지 않는다.
- 보스전에서도 추가 콤보는 허용하지만 직접 보스 피해를 만들지 않는다.

## 6-4. 잊혀진 별방울 - 여운의 응답

### 컨셉 번역

별방울은 장난감이 움직임에 대답하고 아직 살아 있음을 알리는 소리다. 실제 접촉 뒤 잠시 후 한 번 더 울려, 플레이어가 예상하고 활용할 수 있는 지연 타격을 만든다.

### 플레이 규칙

1. 방울에 닿으면 일반 부품 타격이 즉시 발생한다.
2. 방울이 흔들리며 지연 시간을 표시한다.
3. 지연 시간이 끝나면 `여운 타격`이 콤보에 한 번 추가된다.
4. 여운 타격은 콤보 횟수와 유지 시간을 갱신하지만 물리 충돌은 만들지 않는다.
5. 여운 대기 중 추가 접촉은 기본 타격만 인정하고 새 여운은 예약하지 않는다.

### 랭크 수치

| 랭크 | 지연 시간 | 여운 타격 가중치 | 내부 쿨다운 |
|---:|---:|---:|---:|
| 1 | 0.60초 | 0.25 | 1.00초 |
| 2 | 0.50초 | 0.35 | 0.85초 |
| 3 | 0.40초 | 0.50 | 0.70초 |

여운 타격은 `ComboSystem.register_hit(echo_score_weight)`로 처리한다. 효과 컨텍스트는 `SECONDARY_ECHO`로 표시해 다른 수리 부품을 다시 발동하지 못하게 한다.

### 재미 포인트

- 즉시 타격과 늦게 오는 타격 사이에 작은 기대감을 만든다.
- 콤보 타이머가 거의 끝날 때 울리는 여운이 콤보를 구하는 순간을 만든다.
- 방울의 흔들림과 원형 파동으로 소리 없이도 발동 시점을 읽을 수 있다.

### 안전 제한

- 공 하나, 방울 하나당 예약 가능한 여운은 하나다.
- 공 낙하, 웨이브 종료, 재시도 시 예약을 취소한다.
- 여운은 브로치 진행도, 바늘 봉합, 톱니 회전 단계를 갱신하지 않는다.

## 7. 빌드 조합과 실제 플레이 예시

### 7-1. 바늘 → 톱니

바늘에 닿아 달실을 건 뒤 톱니바퀴를 맞힌다. 톱니의 속도 회복과 함께 봉합 타격이 추가되어 콤보가 두 번 오른다. 공은 다시 살아나고 콤보도 이어진다.

### 7-2. 브로치 → 바늘 → 방울 → 브로치

브로치에서 마감 표식을 시작하고, 바늘과 방울을 각각 방문한 뒤 브로치로 돌아온다. 바늘은 중간 경로를 봉합하고, 방울은 귀환 직전 여운으로 콤보 시간을 벌며, 브로치가 큰 완성 보상을 정산한다.

### 7-3. 톱니 반복 배치

반사 경로가 자주 돌아오는 소켓에 톱니를 놓으면 과회전을 노릴 수 있다. 대신 쉬운 소켓 하나를 톱니에 사용하므로 브로치 귀환이나 바늘 연결 배치는 어려워질 수 있다.

### 7-4. 방울 안전망

위험한 상단 소켓에 방울을 놓으면 한 번 맞힌 뒤 공이 긴 경로를 도는 동안 여운이 발생한다. 다음 실물 타격까지의 공백을 메워 콤보 타이머의 안전망 역할을 한다.

## 8. 콤보, 공, 플리퍼, 보스 연동

### 8-1. 콤보 시스템

- 모든 부품의 `PRIMARY` 접촉은 기존 `ComboHitSource`를 통해 기본 콤보 한 번을 적립한다.
- 브로치 완성, 바늘 봉합, 방울 여운은 `RepairComboAdapter`가 `register_hit()`로 추가한다.
- 2차 타격은 부품 접촉 신호를 만들지 않으므로 재귀가 발생하지 않는다.
- 공 낙하 시 기존 콤보 정산이 먼저 끝난 뒤 모든 부품의 임시 상태를 초기화한다.

### 8-2. 공 시스템

- 톱니바퀴만 공의 속도에 직접 영향을 준다.
- 속도 변경은 현재 방향을 보존한 목표 속도와의 차이를 impulse로 적용한다.
- `Pinball.get_limited_velocity()`를 통해 공 종류별 속도 규칙을 유지한다.
- 부품 효과가 `linear_velocity`, `global_position`, `transform`을 지속적으로 덮어쓰지 않는다.

### 8-3. 플리퍼와 패링

- 기본 네 부품은 플리퍼 패링 신호에 직접 의존하지 않는다.
- 패링은 부품 경로를 조준하는 플레이 기술로 자연스럽게 가치가 생긴다.
- 후속 확장 부품이 필요할 때만 `PinballFlipper.parry_resolved`를 별도 어댑터에서 구독한다.

### 8-4. 보스전

- 보스 등장 영역과 겹치는 소켓은 비활성화한다.
- 보스전 진입 직전에 한 번 재배치할 수 있다.
- 부품 타격으로 오른 콤보는 이후 `ComboBossTarget`의 피해 계산에 간접 기여한다.
- 부품 자체가 보스에게 직접 피해를 주지 않는다.
- 방울 여운과 바늘 봉합은 콤보를 올리지만 보스 타격으로 위장하지 않는다.

## 9. 상태 초기화 규칙

| 이벤트 | 브로치 | 톱니 | 바늘 | 방울 |
|---|---|---|---|---|
| 공 낙하 | 표식 제거 | 회전 0 | 실 제거 | 예약 취소 |
| 새 공 발사 | 비활성 | 회전 0 | 비활성 | 예약 없음 |
| 웨이브 종료 | 비활성 | 회전 0 | 비활성 | 예약 취소 |
| 웨이브 재시도 | 전체 초기화 | 전체 초기화 | 전체 초기화 | 전체 초기화 |
| 부품 재배치 | 전체 초기화 | 전체 초기화 | 전체 초기화 | 전체 초기화 |

랭크와 장착 정보만 세션 동안 유지한다. 공 단위 상태를 다음 공으로 넘기지 않는다.

## 10. UI와 피드백

### 10-1. 보드 위 정보

- 부품 이름이나 긴 설명을 보드 위에 표시하지 않는다.
- 준비 가능 상태는 약한 금빛 테두리로 표시한다.
- 쿨다운 상태는 색을 끄는 대신 움직임 강도만 낮춘다.
- 브로치는 별 팔 두 개, 톱니는 회전 단계 세 칸, 바늘은 실, 방울은 퍼지는 원형 파동으로 상태를 구분한다.
- 공과 플리퍼보다 높은 밝기와 크기의 상시 효과를 사용하지 않는다.

### 10-2. 보상 카드 정보

카드는 다음 순서로 읽힌다.

1. 큰 실루엣과 부품 이름
2. 대표 동사 한 줄
3. 발동 조건
4. 현재 랭크 수치와 다음 랭크 변화
5. 추천 배치 힌트

예시 문구는 `다른 부품 둘을 거쳐 돌아오면 수리를 완성합니다`처럼 행동 중심으로 작성한다.

### 10-3. 사운드와 VFX

- 브로치: 별 팔 점등음 두 번, 완성 시 짧은 반짝임과 축하음
- 톱니: 단계별 피치가 올라가는 태엽음, 과회전 시 짧은 풀림음
- 바늘: 실이 걸리는 마찰음, 성공 시 팽팽해지는 짧은 현음
- 방울: 접촉음과 여운음의 두 박자
- 전체 화면 효과는 브로치 수리 완성이나 보스 피격과 겹칠 때만 제한적으로 사용한다.

## 12. 구현 흐름 예시

### 12-1. 접촉 소스

```gdscript
class_name RepairPartHitSource
extends ComboHitSource

signal part_contact_registered(ball: Pinball)

func register_ball_contact(ball: Pinball) -> bool:
    if ball == null:
        return false
    var contact_id := ball.get_instance_id()
    if not register_contact(contact_id):
        return false
    part_contact_registered.emit(ball)
    return true

func release_ball_contact(ball: Pinball) -> void:
    if ball != null:
        release_contact(ball.get_instance_id())
```

### 12-2. 재귀 차단

```gdscript
func dispatch_secondary(context: RepairEffectContext, weight: float) -> void:
    assert(context.trigger_kind != TriggerKind.PRIMARY)
    context.can_trigger_parts = false
    combo_adapter.register_secondary_hit(weight)
    feedback_router.play_secondary(context)
```

### 12-3. 수명주기

`WaveManager.active_ball_changed`, `ball_cycle_resolved`, `wave_won`, `wave_lost`, `wave_retried`를 `RepairSessionController`가 구독한다. 기존 웨이브 관리자를 수정하지 않고 신호 연결만으로 상태를 정리한다.

- 부품 전용 SFX 최종 제작

### 14-3. 제외 범위

- 자유 좌표 배치
- 부품 간 물리 체인이나 로프
- 공 순간이동
- 자동 조준과 강제 경로 이동
- 부품 파괴와 수리 내구도
- 보드 밖에서 상시 적용되는 복잡한 패시브 트리

## 15. 테스트 계획

### 15-1. 단위 테스트

1. 같은 접촉 ID가 분리 전 두 번 발동하지 않는다.
2. 분리 후 재접촉하면 다시 발동한다.
3. 비활성 소켓과 미장착 부품은 발동하지 않는다.
4. 브로치는 서로 다른 두 부품만 방문으로 센다.
5. 브로치 제한 시간이 끝나면 진행도가 제거된다.
6. 톱니는 세 번째 접촉에서 한 번만 과회전한다.
7. 톱니 가속 후 공 속도가 공 고유 최대값을 넘지 않는다.
8. 바늘은 다음 다른 부품의 실제 접촉에서만 성공한다.
9. 바늘 봉합 타격이 새 봉합이나 브로치 방문을 만들지 않는다.
10. 방울은 예약을 하나만 유지한다.
11. 방울 여운이 다른 부품을 발동하지 않는다.
12. 공 낙하와 재시도에서 모든 임시 상태가 제거된다.

### 15-2. 복제 씬 테스트

- 기존 보드 씬을 복제한 테스트 씬에서만 배치한다.
- 공 반지름 22와 실제 보드 속도 범위로 검증한다.
- 각 소켓에 부품을 하나씩 옮겨 끼임, 반복 충돌, 진입 불가를 확인한다.
- 1배속과 1/8배속에서 접촉 중복을 비교한다.
- 네 부품을 동시에 장착해 10분 이상 연속 플레이한다.
- 브로치 완성 중 방울 여운과 바늘 봉합이 겹쳐도 재귀가 없는지 확인한다.
- 보스 등장과 부품 충돌체가 겹치지 않는지 확인한다.

### 15-3. 합격 기준

- 동일 물리 접촉 중 중복 발동 0회
- 공 끼임과 소켓 탈출 불가 0회
- 2차 효과에 의한 재귀 발동 0회
- 공 최대 속도 초과 0회
- 상태 표시와 실제 내부 상태 불일치 0회
- 네 부품 모두 첫 플레이 30초 안에 기본 효과를 관찰 가능

## 16. 밸런스와 지표

### 16-1. 목표 체감

- 부품 하나는 빌드 전체가 아니라 한 가지 판단을 바꾼다.
- 두 부품부터 조합의 재미가 발생한다.
- 세 부품부터 의도적인 경로가 보인다.
- 네 부품은 강하지만 화면과 규칙을 과도하게 복잡하게 만들지 않는다.

### 16-2. 수집할 로그

| 이벤트 | 주요 필드 |
|---|---|
| `part_contact` | wave, ball, part_id, family, rank, socket_id |
| `brooch_finish` | elapsed, visited_families, combo_before, bonus_weight |
| `gear_overdrive` | stack_time, speed_before, speed_after, capped |
| `needle_stitch` | target_family, elapsed, combo_before |
| `bell_echo` | scheduled_at, fired_at, combo_saved 여부 |
| `part_reward_selected` | candidates, selected_id, new_or_rankup |

### 16-3. 1차 튜닝 기준

- 브로치 시작 대비 완성률 25~45%
- 톱니 접촉 대비 과회전 성공률 15~30%
- 바늘 대기 대비 봉합 성공률 55~75%
- 방울 여운이 콤보 종료를 막은 비율 15~35%
- 특정 소켓의 전체 부품 접촉 비중이 평균의 두 배를 넘으면 위치를 조정한다.
- 한 부품 선택률이 45%를 넘거나 10% 미만이면 능력 또는 후보 노출을 조정한다.

## 17. 구현 우선순위

1. `RepairPartDefinition`과 랭크 데이터를 만든다.
2. 기존 보드 씬을 복제해 여섯 개 소켓을 배치한다.
3. `RepairPartHitSource`를 `ComboHitSource` 상속으로 만든다.
4. 공통 런타임과 효과 컨텍스트를 만든다.
5. 톱니와 방울을 먼저 구현해 즉시/지연 발동을 검증한다.
6. 바늘을 구현해 부품 간 실제 접촉 연결을 검증한다.
7. 브로치를 구현해 방문 집합과 귀환 루프를 검증한다.
8. 공 낙하, 웨이브 종료, 재시도 초기화를 연결한다.
9. 시작 선택, 보상 후보, 랭크업을 연결한다.
10. 최소 VFX/SFX 후 통합 밸런스를 조정한다.

## 18. 확정이 필요한 항목

| 항목 | 권장안 | 대안 |
|---|---|---|
| 부품 물리 | 소형 고정 충돌체 + 감지 Area | 통과형 Area 전용 |
| 보드 소켓 수 | 6 | 4 |
| 동시 장착 수 | 최대 4 | 최대 3 |
| 시작 부품 | 세션 시작 시 1개 선택 | 첫 웨이브 후 최초 획득 |
| 브로치 방문 수 | 서로 다른 2종 | 1종 또는 3종 |
| 방울 여운의 콤보 증가 | 증가함 | 시간만 갱신 |
| 랭크업 | 동일 부품 재획득 | 수리 재화 소비 |
